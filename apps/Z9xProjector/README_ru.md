# Проектор (org.z9x.projector), v6.0 (versionCode 6)

Системное приложение нашей сборки Android TV (LineageOS 21 GSI) для проектора XGIMI Z9X.
Оно заменяет то, что в стоковой прошивке делали SystemUI/XRMService/bootanimation XGIMI:
кнопки пульта, автофокус, ручной фокус, трапецию и «рукопожатие» загрузки с вендорским HAL
`xgimi.hardware.gmpf@1.0::IGmpf`. Кода XGIMI в приложении нет.

## Установка в образ

- Путь: `/system/app/Z9xProjector/Z9xProjector.apk` (каталог 0755, файл 0644, `system_file`).
  **Не** `priv-app`: ни одно разрешение не является privileged-only, allowlist не нужен.
- Подпись: платформенный ключ образа (SHA-256 сертификата `c8a2e9bc…2ab8`), v2 + v3.
- `android:persistent="true"`, без `sharedUserId` → SELinux-домен `platform_app`.
- Persistent-приложение нельзя обновить через `adb install -r`: любые изменения = новый образ.
- Аварийное отключение без перепрошивки (root не нужен):
  `adb shell pm disable-user --user 0 org.z9x.projector`, затем `adb reboot`
  (перезагрузка обязательна: `pm` не убивает persistent-процесс). Включить обратно:
  `adb shell pm enable org.z9x.projector`, `adb reboot`.
  `adb root` на первой загрузке поверх свежего /data **не работает**: сначала нужно включить
  Настройки → Об устройстве → 7 раз «Сборка ОС Android TV» → «Для разработчиков» →
  «Отладка суперпользователем» (во время зависшей настройки этот экран открывается командой
  `adb shell am start -a android.settings.SETTINGS`). `pm disable` без `-user` от имени shell
  запрещён (SecurityException).
- Выключатель функций без root (SELinux в permissive): `adb shell setprop persist.z9x.featblock 1`
  (следующая загрузка как v4) или `0` (снова включить), затем `adb reboot`.
- Кнопки работают только вместе с RRO `Z9xFrameworkKeysOverlay` (global_keys) и новыми `.kl`.

## Кнопки пульта (через `GLOBAL_BUTTON` → `KeyReceiver`)

| Кнопка | Keycode | Действие |
|---|---|---|
| Микрофон / AI | `SEARCH` | При нажатии (DOWN) открывает Ассистента (`SearchManager.launchAssist`), пока кнопка держится, идёт голос. Только если `user_setup_complete` и `tv_user_setup_complete` = 1. |
| Фокус (короткое) | `FOCUS` | При отпускании: автофокус (`sendFocusStatus(44)`), подсказка «Автофокус». Не чаще раза в 1 с; игнорируется, пока идёт автофокус. |
| Фокус (долгое) | `TV_CONTENTS_MENU` | Открывает панель «Ручной фокус». |
| Шаг фокуса (другие пульты, ИК, кнопки корпуса) | `MEDIA_STEP_BACKWARD` / `MEDIA_STEP_FORWARD` | Пока держите — мотор едет (1 = «влево» стока, 0 = «вправо»), отпустили — стоп. Только с устройств XGIMI (vendorId 000d, 1d5a, 26e3, 3697, 0001, 9999). |
| Ambient | `TV_SATELLITE_SERVICE` | Запуск заставки (Ambient mode), если заставка включена и ещё не идёт. Только после первоначальной настройки. |
| Keystone / Lens (ИК) | `TV_NETWORK` | Открывает это приложение на разделе «Трапеция». |
| iQIYI | `TV_SATELLITE` (слот 3) | Запуск выбранного приложения. По умолчанию: YouTube (TV), иначе SmartTube, иначе Play Маркет. |
| bilibili | `TV_SATELLITE_BS` (слот 4) | Запуск выбранного приложения. По умолчанию: Play Маркет. |
| Слоты 1, 2, 5 (другие пульты) | `TV_TERRESTRIAL_ANALOG/DIGITAL`, `TV_SATELLITE_CS` | Play Маркет. |

Приложение запускается сначала через leanback-интент, затем через обычный.

Пока первоначальная настройка не завершена (`user_setup_complete` и `tv_user_setup_complete`
не равны 1), кнопки приложений, Ambient и Ассистент ничего не открывают (подсказка «Сначала
завершите настройку»). Автофокус, ручной фокус и панель трапеции работают и во время настройки.
Любое первое нажатие другой глобальной кнопки останавливает мотор, если он едет от `MEDIA_STEP`.

## Панель «Ручной фокус»

Внизу экрана: «Ручной фокус ◀ ▶ OK/Назад — готово».
- При открытии отправляется `manualFocus(17)`.
- ◀ держать → мотор «влево» (1), ▶ держать → «вправо» (0); отпустили → стоп (`manualFocus(2)`).
- Любая другая кнопка сначала останавливает мотор; OK / Назад закрывают панель.
- Потеря фокуса, пауза, закрытие → стоп. Через 8 с без нажатий панель закрывается сама.

## Экран «Проектор» (иконка в лаунчере)

- **Фокус**: «Автофокус сейчас», «Ручной фокус».
- **Трапеция**: «Автотрапеция сейчас» (`autoKst`), «Вписать в экран сейчас» (`newAutoKst(11)`,
  только если включено «Вписывать в полотно»).
- **Автоматика** (значения читаются при открытии, меняются только по нажатию):
  «Автофокус при включении», «Автотрапеция при включении», «Автофокус после перемещения»,
  «Автотрапеция после перемещения», «Вписывать в полотно», «Обход препятствий».
- **Кнопки пульта**: выбор приложения для кнопок iQIYI и bilibili (или «По умолчанию»).
- **Диагностика**: `ro.z9x.version`, `sys.z9x.feat`, `persist.z9x.featblock`,
  `persist.z9x.lastboot`, `vendor.xgimi.ledOn`, работает ли `gmpf_main`, состояние `gmpfHw`,
  подключён ли HAL, этап рукопожатия, `systemUIState`/`bootAnimState`, состояние мотора,
  последние события фокуса.

Если в этой загрузке функции отключены, сверху показано «Функции проектора отключены после
сбоя загрузки», а пункты HAL неактивны. Ассистент, приложения и заставка продолжают работать.

## Рукопожатие загрузки (что приложение отправляет HAL)

Только если `sys.z9x.feat` = `1` (его выставляет `z9x_features.rc`, если прошлая загрузка
с функциями была здоровой). Иначе приложение не делает **ни одного** вызова IGmpf.

1. Ждёт `sys.boot_completed=1` и `vendor.xgimi.ledOn=true` (или 30 с после boot_completed).
   Если процесс перезапустился позже 3 мин после загрузки (boot_completed уже 1 при первой
   проверке), ожидание лампы пропускается, чтобы сразу остановить мотор по флагу.
2. Подключается к `IGmpf/default` (повторы с нарастающей паузой), следит за смертью сервиса.
3. Если сохранён флаг «мотор ехал» → `manualFocus(2)`.
4. 298 `connectProjectorFocusManager` → 306 `setProjectorFocusListener` (один и тот же колбэк).
5. 391 `setSystemUIState(1)` → 237 `goToBootCompleted(0)` (раз за загрузку).
6. Ждёт окончания бутанимации (`init.svc.bootanim`, опрос 100 мс, максимум 180 с).
7. 395 `setBootAnimState(2)` → 237 `goToBootCompleted(1)` (раз за загрузку) →
   307 `sendFocusStatus(17)` последним (раз за загрузку; запускает автофокус при включении).

«Раз за загрузку» привязано к `/proc/sys/kernel/random/boot_id` и сохраняется только после
того, как вызов дошёл до HAL. Если boot_id не читается, защита просто не применяется (не
блокирует навсегда). Внутри одного процесса каждый разовый вызов — не больше двух попыток.

Если HAL перезапустился: переподключение, стоп мотора по флагу, снова 298/306, затем чтение
394/390. Если `bootAnimState` ≠ 2, хотя мы его ставили, — повтор 391(1), 395(2), 237(0), 237(1),
но **не** 17.

Автотрапеция/вписывание выполняются в отдельном потоке и только если сейчас
`systemUIState`=1 и `bootAnimState`=2 (иначе HAL может зависнуть до 300 с). Флаг «идёт
трапеция» ставится сразу при нажатии: повторное нажатие показывает «Подождите: идёт
автотрапеция», а ручной фокус не запускается. Перед вызовом мотор останавливается через поток
мотора, и трапеция выполняется только если остановка подтверждена (мотор стоит и флаг «едет»
снят), иначе «Не удалось выполнить».

События колбэка (все пишутся в лог `Z9xHal`): 4/8/333/334/335 → «Автофокус…»;
2 → «Автофокус не удался»; 0/1 → стоп мотора; 120 → если включено «Вписывать в полотно»,
только подсказка «Изображение сдвинулось: Проектор → Трапеция → «Вписать в экран сейчас»»
(как в стоке: там 120 показывает диалог, а `newAutoKst(11)` идёт только по нажатию). Сама
трапеция по 120 не запускается. Подсказка не чаще раза в 10 с, не раньше 30 с после нашей
трапеции, не больше 5 раз за процесс.

## Правила безопасности (зашиты в код)

- Белый список: в классе `GmpfClient` есть только типизированные методы для кодов
  237, 272, 289–292, 298, 300, 302, 303, 306, 307, 326, 390, 391, 394, 395, 552, 553, 585–588.
  Общего `transact` нет, ни один компонент не принимает коды извне.
- Значения: `manualFocus` только 17/0/1/2; `sendFocusStatus` только 44 и 17; `newAutoKst`
  только 9/11 (используется 11).
- Никогда: `autoFocus` (301), заводские/калибровочные коды (IGmpf 453, 583, IGmpf2 76),
  `setAudioOutput` / `setSoundProcessType` / `setSoundeffect` (ни при загрузке, ни позже),
  `disconnectProjectorFocusManager` (299), вызовы HAL внутри колбэка.
- Ничего не останавливает и не перезапускает `gmpf_main` (только чтение `init.svc.gmpf_main`).
- Все вызовы HAL — в потоках `z9x-hal`, `z9x-motor`, `z9x-kst`; на главном потоке — никогда.
- Мотор: старт только по первому нажатию, флаг «едет» сохраняется до старта (если сохранить
  не удалось — мотор не запускается, «Не удалось выполнить»), сторожевой таймер 700 мс без
  повторов клавиши → стоп, неудачный стоп повторяется каждые 200 мс.
- Все обработчики ловят `RemoteException` и `RuntimeException`; исключение не может
  уронить persistent-процесс в цикл перезапусков.
- Звук: только `Z9xAudioFixer` (снимает ложный mute `STREAM_SYSTEM` после загрузки через
  публичный API, пропускает HDMI ARC/eARC, не чаще 5 раз в минуту). HAL для звука не трогается.
  Работает только при `sys.z9x.feat` = `1` и не раньше BOOT_COMPLETED + `vendor.xgimi.ledOn=true`
  (или 30 с): загрузка с выключенными функциями по звуку такая же, как v4.

## Известные ограничения

- **POWER во время движения мотора.** Кнопка питания до приложения не доходит (её забирает
  `PhoneWindowManager`), а после выключения экрана вендор игнорирует `manualFocus(2)`. Если
  держать кнопку шага фокуса (`MEDIA_STEP_*`) и нажать POWER, мотор может доехать до
  вендорского концевика (защита концевиками у вендора есть). Ранние остановки: отпускание
  кнопки, сторожевой таймер 700 мс, первое нажатие любой другой глобальной кнопки, пауза или
  потеря фокуса панели «Ручной фокус»; `ACTION_SCREEN_OFF` — только запасной вариант.

## SELinux (чтение свойств)

- `sys.z9x.feat` → `system_prop`, входит в `core_property_type`, который читают `appdomain`
  и `coredomain`: приложение видит его и в enforcing.
- `persist.z9x.*`, `ro.z9x.version` → `default_prop` (читает `coredomain`).
- `init.svc.bootanim`, `init.svc.gmpf_main`, `init.svc.gmpfHw`, `sys.boot_completed` — читаются.
- `vendor.xgimi.ledOn` → `vendor_default_prop`: приложениям в enforcing **не** читается
  (сейчас устройство в permissive, читается). В enforcing рукопожатие просто подождёт 30 с
  после boot_completed, в диагностике будет «—». Журнал `z9x_diag` признаёт загрузку здоровой
  не раньше чем через 90 с после boot_completed, а перезапуск `gmpf_main` после этого снова
  ставит `persist.z9x.lastboot=pending`, так что аварийный выключатель срабатывает и тогда.

## v6.4 (versionCode 67): ручная трапеция, AI-звук, эквалайзер

```
cd "gsi/apps" && VERSION_CODE=67 VERSION_NAME=6.4 sh build_apk.sh Z9xProjector
```

- **Ручная трапеция.** IGmpf 186/150/185 работают в координатах DLP-панели 3840×2160 (проверено по
  живому логу: `GM_DISP_KST_CTRL type=10 (200,300)(3594,14)(86,2108)(3798,1968)`; ini панели G0082
  `m_wPanelWidth/Height = 3840/2160`; вендорский полный кадр `0,0|0,2159|3839,0|3839,2159`). v6.3
  проверял углы против 1920×1080 и отказывал («x 3594 not in 0..1920»). Теперь углы проверяются и
  двигаются в пространстве панели (шаг стока 6.0 / 3.375 единиц панели, ускорение до ×16 при
  удержании), на экран 1920×1080 только переводятся для рисования. Все блокировки прежние.
- **AI-звук** снова первый в «Режиме звука», как в стоке: 61(3) + подрежим по приложению на экране
  (IGmpf 63 `setAutoSoundeffect` + свойство `xgimi.pkg.effect.mod`): Кино / Музыка / Спорт / Караоке —
  это 4 настоящие таблицы усилителя. Приложение на экране — из UsageStats; категория — по списку
  пакетов, затем `ApplicationInfo.category`; лаунчер, настройки, HDMI, игры и неизвестные приложения
  ничего не меняют. Не чаще одного переключения в 10 с, приложение должно быть на экране ≥ 2 с, а
  если играет музыка, запущенная раньше (Spotify в фоне), переключение ждёт. В панели: «AI · Музыка».
  Только для встроенного динамика (59-путь 0), не во время HDMI-сеанса.
- **Эквалайзер** (нет в стоке): Звук → Эквалайзер. 7 полос (60, 150, 400, 1k, 2.4k, 6k, 15k Гц),
  ±6 дБ шагом 0.5 дБ (60 Гц — подъём не выше +3 дБ: таблицы усилителя и так режут 60 Гц на 13–21 дБ),
  пресеты «Ровный / Бас / Голос / Ночь / Свой», сброс. Работает на SoC PEQ встроенного динамика
  (IGmpf 50 `SetPEQ`, 51 `SetPEQEnable`), только в режиме Harman Kardon: в DTS Virtual:X вендор сам
  занимает этот PEQ своей настройкой, поэтому там строки неактивны. Суммарный подъём кривой ≤ +6 дБ,
  предусилитель автоматически опускает все полосы, чтобы итог был ≤ +3 дБ. Хранится отдельно для
  каждого режима звука. Повторное применение: после наших 27/44/61, после загрузки (вендор
  восстанавливает эффекты), после включения экрана, после подтверждения аудиовыхода, после
  переподключения HAL. Ровная кривая = PEQ выключен (51(false)).
- Новые разрешения: `MODIFY_AUDIO_ROUTING`, `MEDIA_CONTENT_CONTROL` (signature, даются платформенной
  подписью), `QUERY_ALL_PACKAGES` (normal).

## v6.5 (versionCode 68): ожидание без выключения экрана, никогда STR, настоящее выключение

```
cd "gsi/apps" && VERSION_CODE=68 VERSION_NAME=6.5 sh build_apk.sh Z9xProjector ../overlay/apps_v65/Z9xProjector.apk
cd "gsi/apps" && VERSION_CODE=65 VERSION_NAME=6.5 sh build_apk.sh Z9xTvInput ../overlay/apps_v65/Z9xTvInput.apk
```

- **Короткое нажатие POWER = режим ожидания** (`power/StandbyController`): гаснет только лампа
  (196 → 195(false)), Android и его дисплей остаются включены. Поэтому панель, VB1/TCON, связь с DLPC
  и GOP больше не перезапускаются, и блочного шума в левой нижней четверти после пробуждения быть не
  должно. Сверху — чёрный `StandbyActivity` (забирает кнопки, плееры ставятся на паузу, берётся аудиофокус)
  и чёрная шторка. Будят только действия пользователя: POWER (любой пульт, кнопка на корпусе, ИК-кнопка
  сна 75 тоже `STB_POWER`), OK, HOME; остальные кнопки игнорируются. HDMI не будит никогда (ревью 6.5):
  tvinput сам открывает просмотр при подключении кабеля, повторном HPD/+5V или CEC `<Active Source>`,
  а его проверка «экран включён» в ожидании всегда истинна. Сеанс HDMI во время ожидания только
  пишется в лог, медиа ставится на паузу, лампа перепроверяется и чёрный экран сразу возвращается
  наверх; лампа не горит. Ревью 6.5: `Z9xTvInput` 6.5 (versionCode 65, закреплён sha256) сам спрашивает
  проектор (`power/StandbyStateProvider`, `call()` под подписным разрешением `STANDBY_STATE`) и слушает
  `STANDBY_CHANGED`: в ожидании подключение кабеля, повторный HPD, CEC `<Active Source>` и «открывать
  при загрузке» считаются как «экран выключен» — просмотр и звук HDMI (аппаратный аудиопатч TIF) не
  запускаются. Настройка CEC «включать ТВ по One Touch Play» один раз выключается при первом запуске
  6.5 (`HdmiControlManager.setTvWakeOnOneTouchPlay`), чтобы консоль не будила и обычный сон Android;
  включённую потом в TvSettings мы не трогаем.
  Пока проектор «выключен», ничего не играет: при потере аудиофокуса (AirPlay, Spotify Connect,
  трансляция) все сеансы ставятся на паузу и фокус через 1 с забирается обратно; `STREAM_MUSIC`
  заглушён на всё ожидание (снимается при пробуждении, при SCREEN_ON и при следующем запуске/загрузке,
  если глушили мы; с выходом HDMI ARC/eARC вместо него — общий master mute: mute `STREAM_MUSIC` ушёл бы
  по CEC переключателем на саундбар, а master mute по CEC ничего не шлёт и глушит все выходы AudioFlinger;
  кнопка громкости или приложение, снявшее mute в ожидании, тут же глушится снова); чёрный экран возвращается
  наверх через 1 с после перекрытия и каждые 15 с
  (не чаще 3 раз в минуту). Перед входом — `userActivity`, затем шторка и `StandbyActivity` ставятся до
  того, как заканчивается заставка (stopDream через 150 мс), поэтому нет ни вспышки, ни дозы
  (выключения дисплея). При входе выключаются пользовательские «Коррекция в реальном времени»
  (586 → 585(false)) и «Фокус после перемещения» (588 → 587(false)), если были включены; что выключили —
  в метке, возвращается при пробуждении, SCREEN_ON или следующем запуске. Вендорские события AK/AF во
  время ожидания считаются в логе, `AkOverlay` ничего не показывает и не подтверждает, лампа
  перепроверяется сразу и через 0,5 / 1 / 2 / 4 / 8 с. Так же (ревью 6.5) после событий защиты глаз
  500 / 501 / 601 / 608 (вендорское восстановление может зажечь лампу), начала HDMI-сеанса и каждого
  перекрытия / возврата чёрного экрана.
  Срок выключения и таймер отказа ставятся сразу при входе, не дожидаясь HAL (ревью 6.5): если вызов
  gmpf завис и подтверждения «лампа выключена» нет через 65 с — выключение. В ожидании раз в минуту в лог
  пишутся температуры (thermal_zone0/1, IGmpf 438, только чтение), статус перегрева SEVERE и выше →
  выключение. Неудачное выключение повторяется через 30 с до 3 раз, потом каждые 10 мин, пока проектор
  тёмный; нажатие для пробуждения, пока выключение уже идёт, только пишется в лог (лампа не загорается).
  Системный POWER / TV_POWER (заводские пульты, пульт-приложение на телефоне) при включённом Android
  короткое нажатие больше не усыпляет (`Z9xFrameworkKeysOverlay` 6.5: `config_shortPressOnPowerBehavior`
  = 0), иначе он передавал бы ожидание настоящему сну с перезапуском цепочки дисплея; долгое нажатие —
  системное меню питания, из сна POWER будит как раньше.
  Известные пробелы: Z9xAirPlay не читает `STANDBY_CHANGED` (защищает этот модуль);
  wakeUp() от приложения-пульта на телефоне ожидание не будит, а во время обычного сна Android такой
  wakeUp() или окно с FLAG_TURN_SCREEN_ON зажигают проектор (причину пробуждения Android 14 приложению не
  отдаёт); CEC `<Standby>` устройствам при входе не отправляется (AVR / саундбар / консоль остаются
  включены всё окно ожидания). Не закрыто (решение пользователя): после скачка сети (включение в розетку,
  0xF1 + keypad0) проектор стартует с горящей лампой, как при обычном включении в розетку.
  Пробуждение: 147/148 + 195(true), картинка возвращается за доли секунды (короткое появление без логотипа).
  То же для конца таймера сна и для «Ожидание через» заставки (бывшее «Выключать через»: после него
  идёт ожидание, а уже потом отдельное окно «Режим ожидания, затем выключение через»; переименовано во
  всех 18 наборах строк).
- **Никогда STR.** Каждая попытка STR на этой GSI заканчивалась холодной загрузкой через ~30 с
  (boot_reason 0xF1, без источника пробуждения), т. е. проектор включался сам. Теперь init держит
  ядерный wakelock `z9x_no_str`, а приложение держит `z9x:quickwake`. Когда окно ожидания кончается
  («Режим ожидания, затем выключение через», по умолчанию 30 мин; от «Сразу» до 4 ч; «Никогда» в 6.5
  не предлагается: тепловой режим «дисплей включён, лампа выключена» ещё не измерен, сохранённое
  «Никогда» становится 4 ч), выполняется
  настоящее выключение (`PowerManager.shutdown`, путь `z9x_poweroff`). Лампа не погасла за 60 с,
  или загорелась сама больше 3 раз за час → тоже выключение.
- **Чужие засыпания** (CEC, Ассистент, adb): лампа гаснет как раньше, STR нет, выключение по тому же
  сроку.
- **Таймаут бездействия теперь наш** (`dream/IdleOwner`): `screensaver_activate_on_sleep=1`,
  `sleep_timeout=-1`. После «Запуск через» всегда стартует заставка (дисплей не гаснет); через
  «Ожидание через» — режим ожидания («Никогда» больше нет: заставка держит лампу включённой, сохранённое
  «Никогда» становится 24 ч; если процесс стартовал, когда заставка уже идёт, таймер считается с этого
  момента). Если заставка выключена, активна пустая
  `StandbyIdleDream`, которая сразу переходит в режим ожидания. Выбор заставки сохраняется.
  Первый запуск 6.5: если `screensaver_activate_on_sleep` был не 1 (как на 6.4: через 15 мин лампа
  гасла, заставка не запускалась), заставка выключается, и бездействие сразу ведёт в ожидание; лампа
  не горит часами. `sleep_timeout` берётся как «Выключить через», только если заставка и раньше
  запускалась. `attentive_timeout` («Энергосбережение» TvSettings) тоже забирается в
  «Выключить через» и сбрасывается в -1 (иначе Android гасит дисплей поверх наших wakelock-ов).
- **Тёмная загрузка**: после сброса, о котором никто не просил, проектор входит в ожидание и сразу
  выключается снова. В 6.5 gmpf_main и цепочка дисплея работают всё окно ожидания, поэтому кроме
  сторожевого таймера после STR (0xF1) возможны перезагрузка DrvWdt после рестарта gmpf_main,
  kernel panic или перезагрузка вендора (0xD1). Правило: (1) предыдущее состояние «ожидание» / «сон»,
  нет метки штатного выключения (`ACTION_SHUTDOWN`, его ShutdownThread шлёт при любой перезагрузке и
  выключении из Android; «Перезапуск» в меню питания тоже ставит метку), `sys.boot.reason.last` — не
  штатная причина init (`reboot,…` / `shutdown,…` / bootloader / fastboot), boot_reason 0xF1 или 0xD1,
  источник `(null)`, `wdt_reset_chk=pm51-wdt-reset` (не `no-pm-wdt-reset` = включение в розетку),
  часы RTC не сброшены в 2000 год; или (2) наше выключение меньше 4 мин назад, 0xF1, `(null)`,
  `pm51-wdt-reset` (выключение не удержалось). Не больше 2 раз подряд (счётчик сбрасывает любая
  обычная загрузка); повтор неудачного выключения прекращается при любом нажатии. Состояние
  предыдущей загрузки хранится в метке для текущей, поэтому перезапуск процесса до проверки её не
  теряет; проверка — один раз за загрузку.
- **Перезапуск процесса в ожидании**: метка читается синхронно в `install`, ожидание этой загрузки
  сразу считается активным («ожидает восстановления»), поэтому нажатие POWER, запустившее процесс,
  будит, а не усыпляет.
- **Окно ожидания** читается синхронно при старте процесса. Сохранённое значение 6.4 «0» (= STR
  сразу) один раз превращается в 30 мин, иначе каждое короткое нажатие выключало бы проектор.
- **Кнопка питания без системного запасного варианта** (осознанный компромисс): ИК, кнопки корпуса,
  LAN-пульт и ТВ-пульт дают `STB_POWER` и обрабатываются только этим приложением. Если оно упало,
  система его перезапускает (persistent); при постоянном падении усыпить/выключить проектор можно только
  через adb, заводской пульт (долгое нажатие: системное меню питания) или розетку. Системный POWER на
  корпусе отвергнут: его сон/пробуждение
  перезапускают цепочку дисплея, а именно это даёт блочный шум в четверти кадра.
- **Клавиатуры и прочие пульты без своей раскладки** (ревью 6.5): в образе
  `/product/usr/keylayout/Generic.kl` — копия AOSP, где `key 142` (KEY_SLEEP) = `STB_POWER WAKE` вместо
  `SLEEP` (сон Android с перезапуском цепочки дисплея). Сборка сверяет файл с v4 построчно.
- **Самопроверка без отдельного теста** (`z9x_diag.sh`): на каждое изменение питания в `history.txt`
  пишется `power-check: … display-chain markers=N` — число строк перезапуска цепочки дисплея (LightsHAL
  `[STR check point]`, `close Gwin`, `displayGopOnOff`, `PNL_CUST`, `Panel Driver`, `SetVb1`) с момента
  изменения. Для входа в ожидание и пробуждения из него ожидается 0. Если в pmsg прошлой загрузки есть
  `gmpf_suspend`, хотя STR заблокирован и мы не выключали, — строка `!!! … vendor suspend`.
- Выключатели: `persist.z9x.allow_str=1` (вернуть STR и поведение v6.4 по сроку),
  `persist.z9x.bootdark=0` (не выключаться после самосброса).
