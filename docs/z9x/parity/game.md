## 2. Подробно по пунктам

### 2.1 Выкл / Вкл / Авто: запись (SAME)

Сток: `ST/gmuiapi/manager/DisplayManager.java:3734-3746`.
Lumen: `QPC:1212-1229` onGameMode: 0 = 56(MANUAL) + 57(off); 1 = 648(647) + 56(MANUAL) + 57(on);
2 = 56(AUTO). Совпадает по порядку и значениям. Запись только при HDMI на экране (`hdmiNow`).

### 2.2 Выкл / Вкл / Авто: что показывает строка (DIFF)

Сток читает IGmpf2 55 каждый раз и по ТЕКУЩЕМУ входу (вендор держит состояние на каждый вход:
`m_eGameModeProp[`, libxgimi). Lumen: `QPC:1475-1477` показывает `prefs game_mode` (одно значение на всё),
`L/panel/Snapshot.java:22-24` прямо говорит, что 55 не читается. Следствия:
- переключили HDMI 1 на HDMI 2: строка показывает режим HDMI 1;
- до первой записи строка показывает прочерк;
- если вендор отказал (3D, DV), строка всё равно покажет новое значение (см. 2.3).

При этом формат 55 уже известен: провод проверен (`L/hal/Gmpf2Client.java:150-166`), стоковый
`GameModeProp_st` читает state, type, gameModeOpt именно в этом порядке
(`research/.../xgimi/hardware/gmpf/IDisplayType/GameModeProp_st.java:22-60`), а GP уже умеет проверять
чтение по 647 (`GP:1189-1227`).

Исправление: в `Snapshot` читать 55 (как GP.readGameState, с той же самопроверкой opt == 647, state/type
в {0,1}) и показывать как сток (type==1 => Авто, state==0 => Вкл, иначе Выкл). Pref `game_mode` оставить
только запасным значением, когда 55 не прочитан. GP тогда тоже может брать 55 как основной источник.

### 2.3 Проверка результата включения (DIFF)

`QPC:1216-1227`: результаты 56/57 не проверяются, pref пишется всегда. Вендор отказывает включать игру в 3D
(libxgimi.str:157492 `Error, can not enable Game mode(%d) when 3D(%d) is enabled`) и при открытом VRR/FreeSync
(157399). Сток до этого не доводит: запрет [15] в `common.json` не даёт нажать.

Исправление: перед записью проверить 3D (192 != 1 или 193) и HDR-тип Dolby Vision (620 == 2), показать стоковый
текст («Сначала выключите 3D» / «Действует режим Dolby Vision»); после записи перечитать 55 и, если не совпало,
показать «Не удалось» и вернуть строку.

### 2.4 Скорость: 4 варианта вместо 2 (EXTRA, по виду DIFF)

Сток: две строки, HFR не выбирается, а сохраняется (см. 0.3, `PictureViewModel.java:2279-2287`, `:2443-2455`).
Откуда берётся HFR в стоке: из значения по умолчанию на вход (`Msrv_DataBase_Manage::getDefaultGameOption`,
libxgimi.str:174744) и далее «липко». Какое значение по умолчанию у G0082, проверить не удалось (база вендора
недоступна без root).
Lumen: `QPC:897-901`, `QPC:115-118`: Стандарт, Стандарт+HFR, Турбо, Турбо+HFR (648 = 0/1/3/2).

Это больше, чем в стоке, и само по себе не ошибка. Но есть риск: пользователь может выбрать «Стандарт» (0)
и потерять HFR, которого сток никогда не снимает при выборе «Базовый»; а вендор по HFR выбирает 120-герцовый
EDID и выходной тайминг (libxgimi.str 157495-157497 `match output timing ... bHrrOpt`).

Исправление (на выбор владельца):
- вариант «как сток»: две строки Базовый / Турбо, HFR сохранять по правилу стока (если сейчас 1/2, то 1/2);
- вариант «лучше стока»: оставить 4, но подписи сделать понятными («Стандарт, до 120 Гц»), и при первом
  тесте с PS5 убедиться, что 0 и 1 реально дают 60 / 120 Гц EDID.

### 2.5 Видимость строк (DIFF, мелко)

Сток: «Когда включать (ALLM / приставка)» видно только при Авто; «Базовый / Турбо» только при Вкл.
Lumen: `QPC:1486-1487` обе строки доступны всегда, если на экране HDMI. При Выкл/Вкл строка ALLM к тому же
показывает «С игровой консолью», потому что вендор читает 311 = false, когда тип не AUTO (так написано в `GP:79-82`).

Исправление: строку «Автовключение» показывать только при Авто (по 55 после 2.2). «Скорость» можно оставить
видимой всегда (вендор хранит опцию на вход и применит её, когда игра включится), это удобнее стока.

### 2.6 Турбо: подтверждение перед сбросом трапеции (DIFF)

Сток: если трапеция не нулевая, сначала диалог, и только после «Переключить режим» идёт 648 + сброс.
Lumen: `QPC:1240-1257` сразу 648, потом 207 (`QPC:1277-1290`) и тост «Турбо: коррекция трапеции выключена».
Трапеция пользователя молча сбрасывается.

Исправление: в onGameSpeed для TOP_SPEED и TOP_SPEED_HFR, если трапеция не равна полному кадру (та же проверка,
что `GP:1153-1173` keystoneNeutral, или 186 против `KstPoint.fullFrame()`), показать `confirm(...)` со стоковым
смыслом «В режиме Турбо трапеция и подгонка картинки будут сброшены» и кнопкой «Переключить».

### 2.7 Сброс трапеции после Турбо: не хватает 129 (DIFF, мелко)

Сток `setIChipReset`: 207(0), затем если 130 getCurrentKeystoneMode()==6, то 129 switchKeystoneMode(0,0).
Lumen: `L/hal/GmpfClient.java:610-616` только 207; методов 129/130 в GmpfClient нет.
Что такое режим 6 на Z9X, не установлено. Исправление: добавить 130/129 в GmpfClient и вызывать после 207
так же, как сток (и в QPC.topSpeedKeystone, и в `GP:1057-1075`, и в `GP:1429`).

### 2.8 ALLM: «при сигнале ALLM» / «с игровой консолью» (SAME)

### 2.9 Авто по приставке (EXTRA)

Сток: при Авто + «при приставке» решение принимает вендор (и стоковый tvinput, который не декомпилирован);
список приставок в настройках: Switch, PlayStation, Xbox (`SR/res/values/arrays.xml:64-68`, сравнение с
`xgimi.video.cec.device_name`, `ST/picture/PictureManager.java:155-175`).
Lumen: стоковый tvinput заменён своим (`apps/Z9xTvInput`), он вендору про приставку ничего не сообщает. Вместо
этого GP сам распознаёт приставку (CEC, ALLM ≥ 2 с, вход ≥ 100 Гц, ручная метка «Этот вход: приставка») и
включает игру сам, а когда приставка уходит, всё возвращает (`GP:35-98`). Это больше, чем в стоке.

Замечание: GP включает игру как MANUAL + ON, то есть на время сессии убирает пользовательский «Авто» и
возвращает его при уходе (`GP:1398-1410`). Это правильно, но означает, что строка «Игровой режим» во время
сессии покажет «Вкл» (GP сам пишет pref, `GP:1033`).

Проверка на устройстве (с согласия владельца): PS5 на HDMI 1 с CEC уже определяется
(`dumpsys tv_input`), нужно один раз посмотреть логи `Z9xGame` при включённой PS5.

### 2.10 Авто-переход в Турбо (EXTRA)

`GP:1229-1300` maybeUpgradeToTopSpeed: при входе ≥ 100 Гц и трапеции, которую Lumen знает как полный кадр,
переводит 1 -> 2 и делает 207. Сток так не делает никогда. Хорошо, что трапеция без проверки не сбрасывается.
Pref `top_speed` (по умолчанию true) без строки в интерфейсе (`GP:108`). Исправление: дать строку
«Турбо для 120 Гц игр» на игровой странице (рядом с «120 Гц для консолей»), чтобы это можно было выключить.

### 2.11 «120 Гц для консолей» (EXTRA, риск)

`L/game/GamePanelRows.java:41-48`, `GP:112-114`, `GP:985-989`: при включении профиля 0 переводится в 1.
По умолчанию ВКЛ, на устройстве не проверено (так и написано в коде). Сток такого не делает, у него HFR
приходит из значения по умолчанию.
Риск: PS5 увидит 120-герцовый EDID и может выдать 1080p120 / 1440p120; на 4K60 играх это безвредно, но если
вендор с HFR-опцией откажет в 4K60 HDR, картинка будет хуже стока.
Исправление: до проверки на PS5 поставить по умолчанию ВЫКЛ, либо проверить: (а) что читает 647 на HDMI 1
до любых действий Lumen (это и есть стоковое значение по умолчанию), (б) что после 648(1) PS5 в
«Настройки > Экран и видео > Видеовыход > Информация о видеовыходе» показывает 120 Гц.

### 2.12 Ultra 120 Гц и игра (SAME, сделано лучше)

Вендор при включении игры сам закрывает force_120hz (libxgimi.str:157670). Lumen снимает свою отметку
Ultra 120 и возвращает 161(4) после сессии (`GP:1476-1530`). В стоке возврата нет. Хорошо.

### 2.13 Запрет трапеции/поворота/сброса в Турбо (DIFF)

Сток: запрет только если игра реально идёт (55 state==0) И 647 = 2/3 (`DisplayHelper.java:119-128`).
Lumen:
- `QPC:512-518` (поворот, сброс трапеции) и `QPC:1324-1330`: только `647 == 2/3` (`Snapshot.java:140-142`);
- `L/panel/ManualKeystonePanel.java:412-425`: 647 == 2/3 И вход HDMI (ближе к стоку, но тоже без 55).

Опция хранится на вход и остаётся «Турбо», когда игра выключена. Тогда Lumen запрещает поворот и сброс
трапеции без причины, а сток разрешает. На не-HDMI входе 647 читает опцию того источника, значение не проверено.

Исправление: одна общая проверка `isTopSpeedGameRunning` = HDMI на экране И 55 state==0 (или тип Авто и вендор
включил игру) И 647 = 2/3; использовать её во всех трёх местах. Если 55 не прочитан, вести себя как сейчас.
`support_Trapezoid_GAME=true` означает, что в Базовом трапеция разрешена: так и есть в Lumen.

### 2.14 Режим изображения в игре (MISSING)

Сток: запрет [8] «В игровом режиме режим изображения не меняется». Lumen: `QPC:1104-1131` меняет 667 без
проверки. Что сделает вендор на 667 во время игры, неизвестно (вендор держит свою игровую PQ, `EN_PICTURE_MODE_GAME`).
Исправление: пока игра идёт (55), строку «Режим изображения» делать недоступной с подписью
«В игровом режиме не меняется» (как сток), без вызова 667.

### 2.15 Формат кадра в игре (DIFF)

Исправление: строку перенести на страницу HDMI (рядом с цветовым диапазоном и режимом HDMI) и блокировать,
пока игра идёт, с текстом «В игровом режиме формат кадра не меняется».

### 2.16 3D и игра (DIFF, мелко)

и показывает общий отказ; панельная строка «Игровой режим» 3D не проверяет (см. 2.3).

### 2.17 Dolby Vision (DIFF, мелко)

### 2.18 EDID 1.4 / 2.0 на вход (SAME по смыслу, ЗНАЧЕНИЯ ПОД ВОПРОСОМ)

Сток: «Версия HDMI» 1.4 / 2.0 на текущем входе, вендор хранит на вход
(`Msrv_DataBase_Manage::saveEdidVersion(EN_EDID_VERSION, EN_XGIMI_INPUT_SOURCE)`).
Lumen: `QPC:633-645` «Режим HDMI: Совместимый (1.4) / Улучшенный (2.0)», запись 660, чтение 661, показ только
на HDMI (`QPC:1556-1571`). По смыслу то же.

Но значения расходятся:
- стоковые настройки Z9X шлют `setEdidVersion(1)` для 1.4 и `setEdidVersion(2)` для 2.0, а при чтении
  1 = 1.4, 2 = 2.0 (`ST/signal/SignalManager.java:139-152`, `ST/signal/SignalEnum.java:12-13`);
  `edid_cfg.ini` вендора: `EDID_14:1 , EDID_20:2 , EDID_21:3`;
- Lumen шлёт 0 для 1.4 и 1 (или 3) для 2.0 (`L/hal/GmpfClient.java:308-314`), опираясь на старые константы
  `GmTvManager.EDID_VERSION_14=0, _20=1, _AUTO=2` (`ST/gmpf/api/GmTvManager.java:29-31`), которыми стоковые
  настройки Z9X НЕ пользуются.

Стоковый путь идёт через AIDL `IGmTvManager.setEdidVersion` (транзакция 40), Lumen через HIDL IGmpf 660;
переводит ли что-то значения между ними, по имеющимся материалам не видно. Если перевода нет, у Lumen
«Совместимый» = неизвестное значение 0, а «Улучшенный» = 1 = HDMI 1.4, то есть пункты перепутаны.
Это самое важное, что надо проверить в этой области (касается и PS5: на 1.4 нет 4K60 HDR).

Проверка (одно чтение, с согласия владельца, когда он не смотрит HDMI): на входе HDMI прочитать 661 до любых
изменений. Заводское `eEdidVersion = 3`; если 661 вернёт 2 или 3, а не 1, значит стоковая шкала 1/2/3
и Lumen надо исправить: Совместимый = 1, Улучшенный = 2 (для Z9X, `edid_2_version_val=1`), показ
«Улучшенный» при 2 и 3. Сейчас Lumen при чтении 3 считает это «Улучшенным» (`QPC:1560-1563`), и при выборе
«Улучшенный» запишет 3 (EDID 2.1-файл с FreeSync); стоковый Z9X 2.1 пользователю не даёт.

### 2.19 VRR и FreeSync (SAME, можно сделать лучше)
