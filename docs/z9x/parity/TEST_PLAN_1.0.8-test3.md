### 6.1 Оптический зум: 14 положений (аудит F8)

Ничего не играет (отдельный вызов). Быстрое меню > Трапеция > Оптический зум.

1. **Открытие.** В журнале:
   `enter: 18(true,2) -> true, 121(0) -> 0`,
   `117 -> ret 0 optical 0..12 ...; 153(12,10) limit positions 1`,
   `enter: position P of 0..13`. На экране "Размер N из 14" (N = 14 - P), полоса из 14 делений.
   - Если `153(12,10)` даёт не 1: записать значение. При 0 счётчик будет "из 13" (положения предела нет), вписывание
     откажет (сессия не та модель). Значение больше 4 или меньше 0: строка `not plausible`, счётчик "из 13".
   - Если окно сразу закрылось с "Оптический зум сейчас недоступен": в журнале `enter failed: ...` (например, `13 limit 5`): формат
     ответа IGmpf2 13 не тот. Записать строку целиком, дальше зум не трогать.
2. **До самой большой картинки.** ВПРАВО по одному нажатию (не держать), пока не появится "Это самая большая
   картинка". Ожидается: `119(n) -> 0 in ~450 ms, position k -> k-1` для каждого оптического шага, последний шаг
   `IGmpf2 14(-1) -> 0 in ~900 ms, position 1 -> 0`, у вендора `m_zoomInLimitPos:[1]`. Ещё одно ВПРАВО:
   "самая большая", в журнале ничего не отправлено. На экране "Размер 14 из 14".
3. **До самой маленькой.** ВЛЕВО по одному: первый шаг `IGmpf2 14(0) -> 0, position 0 -> 1`, у вендора
   `m_zoomInLimitPos:[0]`; затем `119(1)` ... `119(12)`, всего 14 положений от "14 из 14" до "1 из 14". Ещё одно
   ВЛЕВО: "Это самая маленькая картинка".
4. **Каждый шаг = один шаг мотора.** Картинка меняется на каждое нажатие одинаково заметно (нет "пустых" нажатий,
   как было в полушаговом режиме). У вендора на каждый 119 одна строка движения примерно на 160 шагов мотора, на 14
   движение к датчику PI и обратно (около 130 шагов). Нигде нет `motor limit front run step err`,
   `Reverse Limit Front Just Exit Pi`, `m_currMotorLimitStep is error`, `zoom run front at limit pos`.
   В журнале Lumen нет `position jumped`, `outside an 18(true,2) + 121 session`, `is not next to the`,
   `may be in the limit zone`, `step failed`.
5. **Клавиши.** Два очень быстрых нажатия ВЛЕВО (меньше 220 мс): один шаг. Держать ВЛЕВО: не чаще шага в 220 мс, после
   отпускания очередь не дорабатывает.
6. **Меню (сброс зума).** С положения около "7 из 14" нажать и отпустить Меню: `MENU zoom reset: 153(5,10) -> 0 in
   ... ms, position k -> 0`, на экране "Размер 14 из 14" и "Зум сброшен". Затем ВЛЕВО: ровно `IGmpf2 14(0)`,
   `position 0 -> 1` ("13 из 14"), без пересинхронизации и без серии шагов.
7. **После автотрапеции (AK).** Закрыть окно (BACK; после движения запускается автофокус, мишень AF видна), запустить
   "Автотрапеция сейчас", снова открыть зум: ожидается "Размер 14 из 14" (AK уводит объектив в положение предела),
   в журнале `AK report: zoom left as XGIMI set it (stock), screen fit=false`, никаких `restore:`. Первый ВЛЕВО =
   `IGmpf2 14(0)`.
8. **OK = сдвиг картинки**, как test2 (5.9 test1): в режиме сдвига стрелки двигают картинку (141), OK обратно к размеру.
9. Вернуть зум, как был у владельца (по счёту из 14: на 1.0.7 "N из 13" примерно соответствует "N из 14", проверить
   глазами по полотну).

Прошло, если пункты 1-7 как описано. Если нет: файлы журнала и фото полотна в
`gsi/docs/z9x/parity/photos/1.0.8-test3/`, зум дальше не трогать.

### 6.3 Вписать по размеру полотна: чтения и калибровка рулеткой

**2026-10-31: раздел не выполнять.** Функция скрыта по решению владельца (пункт 3 в "Что изменилось по сравнению с test2"), код оставлен в дереве.

Строка "Вписать по размеру полотна" есть на странице трапеции (под "Оптический зум"). Подробная методика в
`docs/fit_screen/TEST_PLAN.md`, разделы 1 и 2; коды Z9X в журнале: 18 + 121 / 120, 117, 153(12,10), 116 + IGmpf2 13,
IGmpf2 14 и 119, чтения 173, 279, 584, 186.

1. **Размер полотна.** "Вписать по размеру полотна": ввести диагональ и соотношение (или ширину x высоту по рулетке),
   "Запас от края" 0, "Как вписать": "Не выходить за рамку". Кнопка "Вписать" пока откажет с "Сначала нужна
   калибровка зума": это правильно.
2. **Только чтения (как H1 у HB).** "Калибровка зума" > "2, быстро" > "Начать калибровку" > "Начать", на первом белом кадре BACK.
   Ожидается в журнале:
   ```
   Z9xFit: mount mode 1                                   (1 = потолок, спереди)
   Z9xFit: 279 getTofDistance -> 24xx mm                  три строки, через 1 с, разброс до 30 мм
   Z9xFit: 584 -> acc A0 A1 A2, gyro G0 G1 G2, type T     пять строк, через 100 мс
   Z9xFit: pitch 4.xx deg (acc ..., ceiling)
   Z9xFit: auto keystone -> true
   ```
   - Расстояние: рулеткой от передней части объектива до полотна, перпендикулярно; записать оба числа (M2).
     Постоянная разница больше 2 см идёт в `FitGeometry.offsetMm` до вписывания.
   - Акселерометр: одна из осей около +-4096 (1 g; на столе у этого Z9X z = 4092). У вендора во время AK строка
     `Msensor dir0 = ..., dir1 = ..., dir2 = ...` (`logcat -d | grep "Msensor dir"`): было `294, -22, 4078` = 4,12

     Если ось или знак другие: записать числа, вписывание не запускать (правится `Z9xFitDevice.AXIS_FORWARD` /
     `AXIS_UP` в следующей сборке).

     должно.
3. **Калибровка "Все 14"** (первый раз на модели, это измерение M1). Раздел 2 `docs/fit_screen/TEST_PLAN.md`: на
   каждом положении белая рамка со средней линией, ширину рамки по средней линии рулеткой (от внешнего края левой
   линии до внешнего края правой), ввести стрелками (ВЛЕВО/ВПРАВО 1 мм, ВВЕРХ/ВНИЗ 10 см), OK. Ожидается:
   ```
   Z9xFit: 18(true,2) -> true, 121(0) -> 0
   Z9xFit: 117 -> optical 0..12, 153(12,10) -> 1
   Z9xFit: IGmpf2 14(0) -> 0 in ~900 ms, position 0 -> 1
   Z9xFit: 119(2) -> 0 in ~450 ms, position 1 -> 2        ... до position 12 -> 13
   Z9xFit: calibration position N: WWWW.W mm -> TR T.TTTT
   ```
