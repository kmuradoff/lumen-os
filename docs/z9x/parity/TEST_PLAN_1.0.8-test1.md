## 2. Перед прошивкой

Только когда владелец разрешил и ничего не смотрит. Сначала отдельной командой:

```
adb -s <lan-ip>:5555 shell dumpsys media_session | grep state=
adb -s <lan-ip>:5555 shell dumpsys window | grep mCurrentFocus
```

Если что-то в `PLAYING(3)`, остановиться.

Снять "до" на 1.0.7 (для сравнения):
1. `adb shell dumpsys android.hardware.graphics.composer3.IComposer/default > before_composer.txt`
   (ожидается: нет секций `HWComposerGLComposite info` и `HWC Trapezoid Params`).
2. `adb shell getprop > before_getprop.txt`. Сейчас на проекторе `persist.z9x.kst_prepare=0` (выставлено вручную
   раньше). В 1.0.8 по умолчанию 1; при 0 образ ведёт себя как 1.0.7 (только аппаратная трапеция).
3. Фото трапеции "до" (раздел 6, кадр A).
4. Список пакетов: `adb shell pm list packages -f | grep -E 'org\.(z9x|lumen)' > before_pkgs.txt`.
5. На всякий случай записать, что на главном экране и в избранном Home, какие SMB-папки, пара AirPlay, имена HDMI.

Нужен кабель USB A-A в порту USB 2.0 (fastbootd работает только по кабелю). vbmeta на проекторе уже выключен
(`sys.z9x.vbmeta_cur.flags=3`, `vbmeta_other.flags=3`), повторять не нужно.

## 3. Как прошить (только system, данные остаются)

### Вариант А: установщик (`flash --keep-data`)

На Mac из `gsi`:

```
bash installer/lumen-install.sh \
  --image build/lumen_v1-1.0.8-test1/release/lumen-os-1.0.8-test1-nogms-system.img \
  --keep-data --no-blobs flash
```

- `--keep-data`: пишется только `system_b`, данные не стираются. Попросит ввести `WRITE`.
- `--no-blobs`: раздел `z9x_blobs_b` (кодеки и звук владельца) не трогается и остаётся как есть. Предупреждение
  "не будет звука" к этому случаю не относится: раздел уже есть и подключается при загрузке.
- Если спросит про vbmeta: ответить "да" (сделано раньше), установщик сам проверит, что `system-verity` нет.
- Проверка подписи `SHA256SUMS.sig` пройдёт (подписан ключом OTA), `--unsigned-image` не нужен.
- `z9x_gapps_b` (Google) остаётся, установщик пишет об этом строкой.

### Вариант Б: вручную через fastbootd

```
adb -s <lan-ip>:5555 reboot fastboot      # или по кабелю: adb reboot fastboot
fastboot getvar is-userspace                   # yes
fastboot getvar current-slot                   # b
fastboot getvar snapshot-update-status         # none (иначе не продолжать: дать системе загрузиться)
cd "gsi/build/lumen_v1-1.0.8-test1/release" && shasum -a 256 -c SHA256SUMS
fastboot flash system lumen-os-1.0.8-test1-nogms-system.img
fastboot reboot
```

Ничего больше не писать: ни `-w`, ни vbmeta, ни второй слот. XGIMI fastbootd сам выходит примерно через 2 минуты,
если ничего не делать.

Первая загрузка дольше обычной (ART компилирует, кэш пакетов очищается один раз для нового build id,
LumenImport переносит данные). Если система 3 раза подряд не дойдёт до `sys.boot_completed`, `z9x_rescue`
сам перезагрузит в fastbootd: тогда сразу откат (раздел 4).

## 4. Откат на 1.0.7

Образ 1.0.7 лежит в `gsi/build/lumen_v1-1.0.7/release/lumen-os-1.0.7-nogms-system.img`
(sha256 `0c02701237a8e7b0c15ba70e0136b82acdc3ee28b7e63d881266fd3a4347e8ef`, `SHA256SUMS` и `.sig` рядом).
Это тот же образ, что сейчас на проекторе (build `lumen-1.0.7-20261028anp`).

- Система грузится: тот же вариант А или Б, только с образом 1.0.7:
  `bash installer/lumen-install.sh --image build/lumen_v1-1.0.7/release/lumen-os-1.0.7-nogms-system.img --keep-data --no-blobs flash`
  или `fastboot flash system lumen-os-1.0.7-nogms-system.img` в fastbootd.
- Система не грузится (проектор сам ушёл в fastbootd после 3 неудач): `bash installer/lumen-install.sh
  --image build/lumen_v1-1.0.7/release/lumen-os-1.0.7-nogms-system.img --no-blobs rescue` (ждёт fastbootd до
  15 минут, пишет system без очистки данных) или вариант Б, пока fastbootd открыт.
- Совсем плохо (нет ни adb, ни fastbootd): стоковое восстановление с флешки, `docs/z9x` про USB-stick restore.

Что происходит с данными при откате: старые приложения `org.z9x.*` возвращаются на свои пути с versionCode 104..107,
а в packages.xml записан мост 900000. Для системных приложений Android понижение версии при обновлении system
принимает и данные оставляет. LumenImport только копирует данные в `org.lumen.*` и ничего не удаляет у `org.z9x.*`,
поэтому настройки 1.0.7 должны вернуться такими, какими были до теста. Данные `org.lumen.*` при этом удалятся
(их APK больше нет). Изменения, сделанные во время теста (например, избранное), потеряются. Если после отката
что-то из приложений Lumen не стартует: `adb logcat -d | grep -iE "downgrade|org.z9x"`; крайний случай полная
установка 1.0.7 с очисткой и снова Google через `gapps --zip`.

После теста с `persist.z9x.kst_prepare=1` и отката на 1.0.7 вернуть `adb shell setprop persist.z9x.kst_prepare 0`:
1.0.7 по умолчанию шлёт 18 и без свойств трапеции картинка прыгает (так было до правки).

### 5.1 Мишень AF (исправление 1, критично)

Оптический зум на несколько шагов, выйти, затем AF кнопкой фокуса. Повторить 5 раз подряд.

Ожидается в `logcat -d -s Z9xAfCard`:
```
event 335: AF card shown                (или 4 / 8 / 10 / 333 / 334)
sendFocusStatus(4) <N> ms after the card was added
AF card closed (<event 5|7|2 или timeout>) after <N> ms
sendFocusStatus(5), (3)
```
Не должно быть (общий `logcat -d | grep -E "wait ui open time out|EVENT_FLOW_ERR"`):
`fast_global_focus_wait_UI: wait ui open time out` и `EVENT_FLOW_ERR`. Картинка резкая после каждого раза
(фото до зума и после AF). На мишени: BACK отменяет AF (`AF card closed (...)`, `sendFocusStatus(3), ...`),
LEFT / RIGHT отменяют и открывают ручной фокус. Мишень не появляется поверх окна авто-трапеции
(`event ...: auto keystone overlay active, no AF card`). Плохо: `card window could not be added, vendor will time out`.
