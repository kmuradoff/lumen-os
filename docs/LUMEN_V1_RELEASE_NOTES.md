# Lumen OS 1.0 для XGIMI Z9X: что внутри, как прошить, что проверить

Автор: kmuradoff · дата сборки: 2026-10-07 · база: LineageOS 21 TV GSI (Android 14) + MindTheGapps ATV

Образ: `gsi/build/lumen_v1.img`, 1 263 308 800 байт,
SHA-256 `998e263c3932de87e066a77eaca30d7d12f4628375ce753e0c99924067e0a050`
(записан в `gsi/build/SHA256SUMS_lumen_v1.txt`).

Это **личный (PRIVATE) образ**: кодеки MediaTek лежат прямо в нём, поэтому его нельзя никуда
выкладывать. Образ ещё ни разу не прошивался. OTA-релизов нет, и обновления по воздуху в v1
не запускаются.

## 1. Что нового по сравнению с Z9X OS v6.5.2

**Имя и подписи**
- Везде, где видно пользователю, система называется **Lumen OS 1.0**: «Об устройстве», загрузочная
  анимация «Lumen», окно выключения, программа установки. Внутренние имена `org.z9x.*`,
  `persist.z9x.*` и `ro.z9x.*` не менялись. Модель, бренд и fingerprint устройства тоже прежние,
  как и `userdebug` / `test-keys`.
- **Собственные ключи выпуска.** Все наши APK и все системные APK, подписанные ключами platform,
  shared, media и testkey, переподписаны ключами Lumen на Mac. Итого 67 APK: platform 41,
  releasekey 21, shared 3, media 2. В `otacerts.zip` теперь только ключи Lumen (`ota`, `ota_next`).

**Lumen Home (`org.z9x.home`), главный экран в стиле Google TV**
- Вкладки «Для вас» (крупный баннер, «Продолжить просмотр», ряды каналов приложений), «Приложения»
  (избранное и A–Z) и «Входы» (HDMI, Chromecast, подсказка по AirPlay, плитки проектора).
- Рекомендации берутся только из установленных приложений. Погода определяется по IP
  (Open-Meteo, без ключей) и запрашивается только тогда, когда главный экран на виду. Трейлеры
  по умолчанию выключены.
- Поиск ищет по приложениям (с транслитерацией кириллицы и латиницы), по каналам и программам и по
  истории запросов. Можно искать сразу в YouTube и других приложениях.
- **Кнопка микрофона** открывает поиск Lumen. Голосовой ввод работает через системный распознаватель
  Google, если он доступен. Иначе открывается клавиатура.
- Классический лаунчер Android TV можно выбрать в «Настроить → Главный экран» или в настройке при
  первом запуске. Неактивный лаунчер полностью отключается.

**Первый запуск (`org.z9x.setup`)**
- Язык выбирается первым шагом (по умолчанию английский). Дальше Wi-Fi (часовой пояс определяется
  по IP), пульт, вход в Google (можно пропустить), картинка (автофокус, трапеция, сетка), выбор
  главного экрана и итоговый экран. Шаг «Алиса» пока скрыт.

**Удалено:** Google Assistant (Katniss), Play Фильмы (в том числе из партнёрских данных классического
лаунчера), LineageSetupWizard и ещё около 60 ненужных пакетов. **Chromecast built-in остался.**

**Недавние приложения:** **долгое нажатие HOME** (короткое нажатие открывает главный экран).
OK переключает на приложение, долгое OK закрывает его, есть кнопка «Закрыть все» (force-stop).
После перезагрузки список пуст.

**Питание: настоящий сон (STR)**
- Короткое нажатие POWER, таймер сна, плитка «Сон» в меню питания и простой без действий работают
  одинаково: лампа гаснет сразу, медиа ставится на паузу, Android засыпает, затем сразу засыпает
  процессор (STR). Окна быстрого пробуждения и последующего выключения больше нет.
- Будят проектор ИК-пульт и Bluetooth-пульт. После пробуждения загрузочной анимации нет, и на экране
  то же приложение, что было до сна.
- Источники пробуждения PM51 задаются при загрузке (init): keypad0, ir0, bt-gpio, mute-gpio = 1;
  rtc0, wifi-gpio, uart, voice, dvi0..3, lan, usb, cast = 0; cec0 = 1 только когда включено
  «Включаться от HDMI-устройства».
- Пока подключён USB-хост, STR не включается (раздел 3).
- Остались из v6.5: защита от «тёмной» загрузки, исправленный сторожевой таймер выключения и ручная
  серая сетка трапеции.

**HDMI-CEC, фаза 1:** One Touch Play с отдельными входами для каждого CEC-устройства
(«PlayStation 5 / HDMI 1»). Ночная защита от пробуждения консолью. Настройки CEC собраны в быстрой
панели проектора, на странице «HDMI-устройства (CEC)». Пробуждение от CEC **по умолчанию выключено**.

**Обновления (`org.z9x.updater`):** раздел «Об устройстве → Обновление Lumen OS». Приложение и
инструменты готовы, но опубликованных релизов нет, поэтому сейчас оно просто ничего не найдёт.
Первое обновление в слот A сначала спросит согласие (см. раздел 5).

**AirPlay** берёт имя проектора из настроек (то, которое задаётся при первом запуске), если
отдельное имя для AirPlay не сохранено.

**Скорость и память:** настроены lmkd (10/30/700), swappiness 100, лимит фоновых процессов 16 и
потоки ART. Системные приложения заранее скомпилированы (dexpreopt), кэш разбора пакетов включён.

**Безопасность:** после очистки данных отладка по USB **выключена**. Когда вы её включите, экран
попросит подтвердить RSA-ключ компьютера (`ro.adb.secure=1`). Статистика LineageOS не отправляется.

## 2. Прошивка с полной очисткой данных

**Будут стёрты все данные проектора:** приложения, аккаунты, настройки, файлы. Калибровка XGIMI
(persist, xgimi*), vendor, boot, vbmeta и второй слот (A) **не затрагиваются**.

### 2.1. vbmeta делать НЕ нужно

Проектор сейчас работает в **слоте B**, и vbmeta для слота B вы уже прошили раньше (на нём работала
v6.5.2). Повторять этот шаг не нужно. Программа установки всё равно задаст вопрос
«Вы сделали шаг vbmeta…?». Ответьте **да**: сама программа vbmeta никогда не трогает.
vbmeta для слота A понадобится только перед первым обновлением по воздуху (раздел 5).

### 2.2. Подготовка

1. Проектор работает на v6.5.2, отладка по USB включена, кабель A–A вставлен в порт **USB 2.0**.
2. По желанию: флешка для логов. Создайте в корне флешки папку `z9x_diag_logs` и вставьте флешку в
   синий порт USB 3.0. Без этой папки логи на флешку больше **не** копируются.
3. По желанию: резервная копия ваших приложений и файлов (без данных приложений):
   ```
   cd ~/"XGIMI PLAY 6/gsi"
   bash installer/lumen-install.sh --lang ru --image build/lumen_v1.img --unsigned-image --blobs=embedded backup
   ```

### 2.3. Проверка образа и проектора (ничего не записывает)

```
cd ~/"XGIMI PLAY 6/gsi/build" && shasum -a 256 -c SHA256SUMS_lumen_v1.txt
cd ~/"XGIMI PLAY 6/gsi"
bash installer/lumen-install.sh --lang ru --image build/lumen_v1.img --unsigned-image --blobs=embedded check
```
- Первая команда должна напечатать `lumen_v1.img: OK`.
- `--unsigned-image` нужен потому, что у личной сборки нет подписанного `SHA256SUMS.sig`. Программа
  попросит ввести `UNSIGNED` и сверит контрольную сумму по `SHA256SUMS_lumen_v1.txt`.
- `--blobs=embedded` нужен потому, что кодеки MediaTek уже внутри образа. Без этого флага
  программа остановится: она сама видит кодеки в образе.

### 2.4. Прошивка

```
cd ~/"XGIMI PLAY 6/gsi"
bash installer/lumen-install.sh --lang ru --image build/lumen_v1.img --unsigned-image --blobs=embedded flash
```
Что спросит программа:
1. `UNSIGNED`, если не вводили при проверке.
2. Вопрос про vbmeta: ответьте **да** (см. 2.1).
3. `ERASE`: подтверждение полной очистки.

Дальше всё идёт одной короткой сессией fastbootd (меньше 2 минут):
1. Удаляются остатки `*-cow` и неиспользуемые `product_b`/`system_ext_b`, если они есть.
2. Записывается system (около 40 с).
3. Выполняется `fastboot format` для userdata, metadata и cache. Никаких `-w` и `erase`: на Z9X
   они приводят к зависанию при загрузке.
4. Проектор перезагружается.

Первый запуск занимает 2–4 минуты, затем открывается настройка Lumen (по-английски, первый шаг —
язык).

**Если программа установки откажется** (например, из-за проверки версии прошивки XGIMI), прошейте
вручную. Это те же шаги, все в одной сессии, без пауз:
```
cd ~/"XGIMI PLAY 6/gsi"
adb -s <SERIAL> reboot fastboot
fastboot getvar current-slot          # должно быть: b
fastboot getvar all 2>&1 | grep -E "snapshot-update-status|-cow"   # статус none, без *-cow
fastboot flash system build/lumen_v1.img
fastboot format userdata
fastboot format metadata
fastboot reboot
```
**Никогда** не используйте `fastboot -w`, `fastboot erase …` и `adb reboot bootloader`.

### 2.5. После первого запуска

1. Пройдите настройку. Вход в Google можно пропустить и сделать позже.
2. Включите adb: Settings → Device preferences → About → 7 раз нажмите «Build». Затем
   Developer options → **USB debugging** и подтвердите RSA-ключ Mac на экране. Для root ещё включите
   **Rooted debugging** (Отладка суперпользователем).
3. Проверка и GSF ID для https://www.google.com/android/uncertified:
   ```
   cd ~/"XGIMI PLAY 6/gsi"
   bash installer/lumen-install.sh --lang ru verify
   bash installer/lumen-install.sh --lang ru gsf
   adb shell getprop ro.lumen.version     # 1.0
   ```
4. Для проверки сна **выньте кабель USB** (раздел 3).

## 3. Кабель USB и сон: почему кабель нужно вынимать

Сон работает по-настоящему, только когда **кабель USB к Mac отключён**.

**Почему.** Пока к порту USB 2.0 подключён компьютер (USB-хост), USB-контроллер проектора держит
включённым свой тактовый сигнал. Микроконтроллер питания PM51 не может обесточить чип
(«can not power down because clk is enable») и через 20 секунд **перезагружает** проектор
(boot_reason 0xF1). Именно это было причиной всех самопроизвольных перезагрузок 6 октября.

**Что делает v1.** Если подключён USB-хост (UDC в состоянии «configured» или adb по кабелю),
проектор в STR **не уходит**. Он остаётся в прежнем «ламповом» режиме ожидания: лампа выключена,
процессор работает, перезагрузок нет. Как только кабель вынут, в течение примерно 15 секунд
проектор засыпает по-настоящему. Поэтому:
- для проверки сна, пробуждения и ночной работы **кабель должен быть выдернут**;
- с кабелем проектор просто «тёмный», но не спит. Это нормально, а не ошибка;
- логи без кабеля: adb по сети (`adb connect <IP проектора>:5555`, RSA подтверждается на экране).
  Во сне сеть отключена, поэтому подключаться нужно после пробуждения.

Экспериментальный вариант на будущее, сейчас **выключен**: `persist.z9x.str_usb_drop=1`. В нём
проектор перед сном отключает USB-гаджет, а после пробуждения возвращает. Без отдельной договорённости
его не включайте.

## 5. Известные ограничения v1

- **Обновлений по воздуху пока нет**: релиз не опубликован, OTA в v1 не запускается. Перед первым
  обновлением в слот A нужно будет **вручную** прошить vbmeta для слота A и **отдельно разрешить**
  копирование прошивки XGIMI без изменений в слот A. Программа обновления сама спросит об этом
  заранее и ничего не сделает без вашего согласия.
- **APEX-модули не переподписаны** (около 30 модулей `com.android.*`). Они остаются на ключах AOSP.
  Из-за общего uid с модулем tethering `NetworkStack.apk` и `CaptivePortalLogin.apk` тоже сохраняют
  тестовый ключ networkstack. Подробности в `docs/keys.md`, раздел «APEX policy».
- Сборка `userdebug` с метками `test-keys` (так и задумано, fingerprint не меняется). SELinux
  работает в режиме permissive.
- Устройство не сертифицировано Google: для входа нужно зарегистрировать GSF ID.
- Голосовой поиск зависит от распознавателя Google. Если тот не работает, открывается клавиатура.
  Постоянные ошибки распознавания отключают голос на 24 часа.
- Шаг «Алиса» скрыт (Алиса через Yaha Cloud будет позже).
- HDMI-CEC только в объёме фазы 1. Патч фреймворка отложен. На Z9X CEC ещё ни разу не проверялся.
- **Не проверено на устройстве:**
  - удержание лампы при CEC-пробуждении;
  - что круглая кнопка микрофона классического лаунчера шлёт `search_type 1`;
  - число опросов лампы после STR (`persist.z9x.str_lamp_polls`, по умолчанию 3; на v6.5.2 нужно
    было 7). Если картинка после пробуждения долго чёрная или лампа мигает, скажите;
  - время загрузки.
- При подключённом USB-кабеле настоящего сна нет (раздел 3). `str_usb_drop` ещё не проверен.
- Управление вентилятором через HAL на Z9X физически не работает и не используется.
- Программа установки для Windows не запускалась ни разу.
- **Откат на v6.5.2** тоже требует полной очистки: ключи подписи другие, и данные Lumen не подходят
  к v6.5.2. Команда та же, только с другим образом:
  ```
  cd ~/"XGIMI PLAY 6/gsi"
  bash installer/lumen-install.sh --lang ru --image build/system_tv_v652.img --unsigned-image --blobs=embedded flash
  ```

## 6. Ключи: где лежат и как сохранить

**Где:** `~/.lumen-keys/` **только на этом Mac**. Права на папку `700`, на файлы `*.pk8` — `600`.
**Паролей нет**: кто получит эту папку, тот сможет подписывать системные обновления для любого
проектора с Lumen OS.

| Файл | Для чего |
|---|---|
| `platform`, `shared`, `media`, `releasekey` | подпись системных APK и всех приложений `org.z9x.*` |
| `networkstack`, `bluetooth`, `nfc`, `sdk_sandbox` | запас: в 1.0 их пакеты живут внутри APEX |
| `ota`, `ota_next` (RSA-4096) | подпись обновлений и манифестов; `ota_next` — запасной ключ для одной будущей смены |
| `README.txt`, `FINGERPRINTS.txt` | описание и отпечатки SHA-256 |

Публичные сертификаты (их публиковать можно) лежат в `gsi/tools/sign/release_certs/`, вместе с
отпечатками в `FINGERPRINTS.txt`. В `~/.config/lumen/key_hashes` хранятся только хэши ключей для
защиты от случайной публикации. Это не ключи, но и этот файл тоже не публикуйте.

**Что будет при потере.** Без `platform` следующую систему можно будет поставить только с полной
очисткой данных. Без `ota` обновления по воздуху на уже установленные проекторы станут невозможны.

**Резервная копия: сделайте один раз, две копии офлайн.**
1. Зашифрованный архив на флешку (пароль придумайте и сохраните в менеджере паролей):
   ```
   cd ~ && tar -czf - .lumen-keys | openssl enc -aes-256-cbc -pbkdf2 -iter 200000 -salt \
     -out /Volumes/<ФЛЕШКА>/lumen-keys-2026-10-07.tar.gz.enc
   ```
2. Тот же `.enc`-файл положите вложением в менеджер паролей (вторая копия).
3. Проверьте, что архив расшифровывается (в папку-песочницу, не поверх настоящих ключей):
   ```
   mkdir -p /tmp/lk && openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 \
     -in /Volumes/<ФЛЕШКА>/lumen-keys-2026-10-07.tar.gz.enc | tar -xzf - -C /tmp/lk \
     && diff -r ~/.lumen-keys /tmp/lk/.lumen-keys && echo OK; rm -rf /tmp/lk
   ```
4. Восстановление на новом Mac:
   ```
   openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in lumen-keys-….tar.gz.enc | tar -xzf - -C ~
   chmod 700 ~/.lumen-keys && chmod 600 ~/.lumen-keys/*.pk8
   ```
   Затем сверьте `~/.lumen-keys/FINGERPRINTS.txt` с `gsi/tools/sign/release_certs/FINGERPRINTS.txt`.

**Куда ключи класть нельзя:** в папку проекта `gsi/`, на ноутбук-сборщик, в git, в iCloud или
Dropbox, в чат, в незашифрованную резервную копию. Если включён Time Machine, его диск должен быть
зашифрован. Скрипты подписи (`sign_tar.py`, `sign_payload.py`, `make_manifest.py`) откажутся
работать с папкой ключей внутри проекта, а `check_publish.py` не пропустит закрытый ключ в
публикацию.
